Test 1 (patch 1): netconsole over ibmveth under load — AFTER only
---------------------------------------------------------------------
Receiver R (another host on the same VLAN):
  nc -u -l 6666 | tee netcons.log         # or: socat -u UDP-RECV:6666 -

On the LPAR:
  Netconsole module (CONFIG_NETCONSOLE=m):
    modprobe netconsole netconsole=6665@<LPAR_IP>/ETH,6666@<R_IP>/<R_MAC>
  Built in (=y) with CONFIG_NETCONSOLE_DYNAMIC=y, at runtime:
    T=/sys/kernel/config/netconsole/t1; mkdir $T
    echo ETH > $T/dev_name; echo 6665 > $T/local_port
    echo <LPAR_IP> > $T/local_ip; echo <R_IP> > $T/remote_ip
    echo 6666 > $T/remote_port; echo <R_MAC> > $T/remote_mac  # optional
    echo 1 > $T/enabled          # stop: echo 0 > $T/enabled; rmdir $T
  Built in without DYNAMIC: add to the kernel command line and reboot:
    grubby --update-kernel=/boot/vmlinuz-$(uname -r) \
      --args="netconsole=6665@<LPAR_IP>/ETH,6666@<R_IP>/<R_MAC>"
  dmesg | grep -i netconsole               # "netconsole: network logging started"
  echo "netcons test" > /dev/kmsg          # must show up on R (dmesg -n 8 if not)

  # load on the same interface (iperf3 -s on R)
  iperf3 -c <R_IP> -P 8 -t 300 &
  # printk flood while TX is busy
  for i in $(seq 1 20000); do echo "ibmveth netcons $i" > /dev/kmsg; done
  echo t > /proc/sysrq-trigger             # large burst (task dump)
  wait

Pass:
  - R receives the "ibmveth netcons N" lines and the sysrq dump
    (count: grep -c 'ibmveth netcons' netcons.log; some loss under
    load is fine, netpoll is best effort).
  - iperf3 keeps running; no WARN/oops in dmesg on the LPAR
    (in particular no "exceeded budget in poll").
  - ip -s link show ETH: RX/TX counters still moving afterwards.
  Then, with netconsole still loaded (patch 1, netpoll during the
  driver's internal close/open):
  for i in $(seq 1 50); do
    ip link set dev ETH mtu 9000; ip link set dev ETH mtu 1500
    ethtool -K ETH tso off; ethtool -K ETH tso on
  done &
  for i in $(seq 1 20000); do echo "ibmveth netcons $i" > /dev/kmsg; done
  wait
  Pass: no oops/WARN, ETH still passes traffic afterwards.
~15-20 minutes. No BEFORE run needed: the race itself is not
reproduced; this shows netconsole still works without the callback.

Test 2 (patch 2): forced open() failure on an MTU change
---------------------------------------------------------------------
On the LPAR (ETH up, with an IP, pingable):
  ip link show ETH                         # note current MTU
  echo 1 > /sys/module/ibmveth/parameters/debug_fail_open
  ip link set dev ETH mtu 9000             # expect: Cannot allocate memory
  dmesg | tail                             # "debug_fail_open: failing open"
  ip link show ETH                         # still UP (IFF_UP stays set)
  ip link set dev ETH down

BEFORE expected:
  - "ip link set dev ETH down" never returns.
  - After ~120s dmesg shows "task ip:... blocked for more than 120
    seconds" with napi_disable() / ibmveth_close() in the stack.
    Save that dmesg (it is the validation evidence).
  - Any other "ip"/"ethtool" command also hangs (RTNL held).
  - Restart the LPAR from the HMC.

AFTER expected:
  - "ip link set dev ETH down" returns at once.
  - ip link set dev ETH up                 # succeeds (knob is now 0)
  - ping <peer> over ETH works; ip link show ETH shows mtu 9000.
  - Optional: repeat with "ethtool -K ETH tso off" and with
    echo 0 > /sys/devices/vio/<unit>/pool2/active style pool changes
    instead of the MTU change; same result.
